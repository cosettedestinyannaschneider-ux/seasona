# 数据模型与状态机说明

本项目的表结构以 SQLAlchemy 模型为准，`docs/schema.sql` 是当前模型翻译出的 PostgreSQL 建表参考。项目暂未引入 Alembic 迁移系统。

## 保留的设计决策

- `wallet_account.version`：钱包乐观锁版本字段。
- `product_sku.version`：SKU 乐观锁版本字段，用于库存并发更新检测。
- `product_sku.stock_locked`：订单创建后、付款/取消/完成前的库存锁定量。
- `product_traceability.trace_code`：面向用户展示的溯源码。
- `product_category.parent_id`：分类树结构。
- `product_review`：评论独立成表，并关联订单明细与 SKU。

## 已删除或不采用的设计

- 不再保留商品别名表。
- 不再保留 SPU 副标题字段。
- 不再保留 SPU `search_text` 字段。
- 不再保留 SKU 编码字段。
- SKU 不单独设置上下架状态，是否可购买由 SPU 状态、商家审核状态、卖家账号状态、分类状态和库存共同决定。
- 不再使用 Elasticsearch、pgvector 和独立商品向量表。

## 商品模型

- SPU 表达一个商品主体，例如“赣南脐橙”。
- SKU 表达同一商品下的不同规格，例如“5斤装”“10斤装”。
- 商品封面图主要用于列表展示，商品图集用于详情页轮播。
- 商品溯源信息与 SPU 一对一，可为空；前端只展示商家填写过的字段。

## 搜索与 AI 派生数据

- Meilisearch 商品文档是 SPU 级派生索引。
- 首页搜索和小拾食材匹配共用同一个 Meilisearch 索引。
- PostgreSQL 始终是商品、价格、库存、订单、退款、钱包和评论的事实数据源。
- 搜索结果只用于展示候选商品，真正下单时必须回 PostgreSQL 重新校验。

## 订单状态

主订单状态由 `purchase_order.status` 表示：

- `wait_pay`：待支付。
- `paid`：已支付，未发货。
- `shipped`：已发货，待确认收货。
- `completed`：已完成。
- `cancelled`：已取消。
- `expired`：待支付超时。
- `refunded`：已退款。

关键辅助字段：

- `paid_at`：买家资金被冻结的时间。
- `is_shipped`：是否已发货，是取消和退款的核心边界。
- `shipped_at`：卖家发货时间。
- `payment_expires_at`：待支付超时时间。

卖家侧订单查询只展示已付款后的订单，待支付阶段对卖家不可见。

## 资金状态

- 充值：增加买家可用余额。
- 支付：减少买家可用余额，增加买家冻结余额。
- 未发货取消：释放库存，并把买家冻结余额退回可用余额。
- 确认收货：扣除买家冻结余额，增加卖家可用余额。
- 已发货退款：释放库存，并把买家冻结余额退回可用余额。
- 已完成退款：扣减卖家可用余额，增加买家可用余额。

钱包流水只对外展示实际落地的资金流入/流出；冻结、解冻等内部中间状态不作为普通流水展示。

## 退款与争议

- 买家只能对已发货或已完成订单申请退款。
- 未发货订单应直接取消，不走退款。
- 退款申请首先由卖家处理。
- `seller_deadline_at` 是卖家三天处理期限。
- `seller_handled_at`、`seller_note`、`seller_handler_id` 记录卖家处理结果。
- 等待卖家处理时买家不能主动发起争议。
- 卖家拒绝或三天超时后，买家可以进入争议流程。
- 争议由管理员处理，处理后订单、退款、钱包和库存一起进入最终状态。

## 并发控制

- 库存变更使用 SKU 行级锁。
- 钱包变更使用钱包账户行级锁。
- 订单支付、取消、发货、完成、退款、争议处理均先锁定订单。
- 钱包流水有业务唯一约束，避免幂等重试导致重复入账或重复扣款。
- 购物车结算幂等键按买家和商家拆分，避免不同买家之间互相冲突。
